# 要件定義 — コメントボード Mock

## 意図の分析

Web ページで入力したコメントを DynamoDB テーブルへ保存し、同じページで一覧表示するだけの、非常にシンプルな Mock レベルの Web アプリケーションを素早く作る。実 AWS 環境へデプロイして動作を確認できることがゴール。コンストラクションは 2 名で UNIT を分担して進める。何よりも実装スピードを優先する。

出典: Initial description（project-description.json）、確認質問 Q1〜Q4（`requirements-analysis-questions.md`）。

## 機能要件

### FR1 コメント投稿
- **FR1.1** Web ページはコメント本文の入力欄と投稿ボタンを持つ。
  - 合否基準: Given ページを開いている、When 本文を入力して投稿ボタンを押す、Then 保存 API が呼ばれ、入力欄が空になる。
- **FR1.2** バックエンドは受け取ったコメントに一意 ID と保存時刻（UTC, ISO 8601）を自動付与し、DynamoDB テーブルへ保存する。
  - 合否基準: Given 本文 "hello"、When 保存 API を呼ぶ、Then HTTP 201 と、ID・本文・保存時刻を含む JSON が返り、テーブルに 1 件追加される。
- **FR1.3** 本文が空（空白のみを含む）または 500 文字を超える場合、保存せずエラーを返す。
  - 合否基準: Given 空の本文、When 保存 API を呼ぶ、Then HTTP 400 とエラーメッセージが返り、テーブルは変化しない。画面にはエラーメッセージを表示する。

### FR2 コメント一覧表示
- **FR2.1** バックエンドは保存済みコメントを保存時刻の新しい順で返す一覧取得 API を持つ。
  - 合否基準: Given コメントが 2 件保存済み、When 一覧取得 API を呼ぶ、Then HTTP 200 と、新しい順に並んだ 2 件の JSON 配列が返る。0 件なら空配列を返す。
- **FR2.2** Web ページは表示時と投稿成功時に一覧を取得し、本文と保存時刻を新しい順に表示する。
  - 合否基準: Given 投稿が成功した、When 画面が更新される、Then 投稿したコメントが一覧の先頭に表示される。
- **FR2.3** 一覧取得に失敗した場合、画面にエラーメッセージを表示する。
  - 合否基準: Given API が応答しない、When ページを開く、Then 「コメントを取得できませんでした」相当のメッセージが表示される。

## 非機能要件

- **NFR1 デプロイ**: DynamoDB テーブル・API・Web ページを IaC で実 AWS アカウントへ 1 コマンドでデプロイ・削除できる。合否基準: デプロイコマンド完了後に出力される URL でページが開ける。削除コマンドで作成したリソースが残らない。
- **NFR2 応答性（Mock 水準）**: 一覧 100 件までの状態で、保存・一覧取得 API が通常時 1 秒以内に応答する。
- **NFR3 セキュリティ（Mock 水準）**: 認証なしの Mock とする。認証情報・シークレットをコードに埋め込まない。HTML 表示時は本文をテキストとして描画し、スクリプトを実行させない（XSS 防止）。DynamoDB はサーバー側暗号化（既定）を使う。Lambda の IAM 権限は対象テーブルへの書き込み・読み取りのみに絞る。
- **NFR4 テスト**: 要件ごとに 1 つ以上のユニットテスト（Minimal 戦略）。

## 制約

- バックエンド: AWS Lambda（Node.js / JavaScript）+ API Gateway [Q2, Q3]
- データストア: Amazon DynamoDB [desc]
- 実行環境: 実 AWS アカウントにデプロイ [Q3]
- UNIT 分割（2 名で並行開発）[Q4]:
  - **UNIT1 フロントエンド**: Web ページ（投稿フォーム + 一覧表示）
  - **UNIT2 バックエンド**: 保存 API・一覧取得 API + DynamoDB テーブル + IaC
  - API の入出力仕様を先に取り決め、両 UNIT を並行開発する。
- スピード最優先。Mock レベルのため機能は最小限 [desc]

## 前提

- [assumption] IaC は AWS CDK（JavaScript）を使う。静的ページは S3 + CloudFront で配信する（スピード重視で AI が選択。SAM 希望なら変更可）。
- [assumption] リージョンは ap-northeast-1（東京）。
- [assumption] デプロイ用の AWS 認証情報は開発者のローカル環境に設定済み。
- [assumption] 一覧は DynamoDB の Scan で全件取得し、Lambda 内で新しい順に並べる（Mock のため件数は少ない前提）。
- [assumption] フロントエンドはビルド不要の素の HTML / JavaScript とする。

## 対象外

- 監視・アラート、CI/CD パイプライン、複数環境（staging/production）
